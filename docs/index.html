Epistemic Programming Interface

Epi

A type discipline for AI-augmented full-stack applications.

Containing LLM hallucination at the type-system boundary, by construction, in generated code.

The problem

LLMs are increasingly embedded in production software, but the languages we use to build that software were designed for an era when all computation was deterministic. Three problems follow.

1. No type-level separation of epistemic domains

In TypeScript or Python, a database field status: String and an LLM-inferred field risk: String are treated identically by the type system. If the LLM hallucinates "Unknown", the value lands in the database. Nothing in the compiler or runtime requires validation.

2. Forced stack fragmentation

Building an AI-augmented application means juggling SQL/Prisma, TypeScript, React, and an LLM SDK at the same time — four mental models for a single feature.

3. No grammar-enforced hallucination contract

Validation, retries, fallback handling, confidence thresholding, and audit trails are all optional. They are features the developer must remember to add. In practice, they are forgotten.

The thesis

LLM hallucination cannot be prevented. It can, however, be contained at a type-system boundary, by construction, in the generated code.

Epi defines an epistemic type system: every value belongs to one of two domains.

Rigid types

Deterministic, no AI involvement.

UUID · Text · Int · Decimal · Bool · DateTime · JSON

Epistemic types

AI-inferred, runtime-validated at the boundary.

AI.Enum · AI.Text · AI.Classification · AI.Score · AI.Embedding

A single epistemic declaration generates: a database column, a Zod validator, an LLM inference call with confidence reporting, and a checkpoint route that pauses for human review when confidence falls below threshold. The validation is not optional — it is emitted by the transpiler.

What an Epi program looks like

The full source of contrato-simples.epi — the quickstart bundled with epi init:

@Language: Epi v0.3
@Goal: "Minimal contract classification"
@Database: sqlite

Entity Contrato {
    id: UUID(auto),
    documento: Text,
    criado_em: DateTime(auto),
    risco: AI.Enum(
        Alto, Medio, Baixo,
        strict: true,
        confidence_threshold: 0.7
    )
}

Guard SomenteAdvogados {
    Condition: Auth.Role == "Lawyer"
}

Pulse ClassificarRisco {
    Input: Contrato
    Protect: Guard.SomenteAdvogados
    Process:
        Execute: AI.scan(
            source: Input.documento,
            prompt: file("@prompts/legal_scan_simples.md"),
            temperature: 0.1,
            confidence_threshold: 0.7,
            on_low_confidence: Checkpoint.ReviewRequired(role: "Lawyer"),
            on_fail: Fallback.ManualReview(Queue: "Advogados")
        )
    Output: Contrato.risco
}

Pipeline AnalisarContrato {
    Flow: ClassificarRisco
    On_Error: Retry(max: 2, backoff: exponential)
}

From these ~30 lines, the transpiler generates a complete runnable Next.js project: Prisma schema, auth middleware, API routes, Zod validators, LLM inference functions, and a provider-agnostic lib/llm-client.ts. Run epi transpile and you get a 13-file project ready to npm install && npm run dev.

Three-layer transpiler

The LLM is formally excluded from Layers 1 and 2:

.epi source
   ▼
[Layer 1: Parser]            Lark + EBNF             100% deterministic
   ▼
[Layer 2: Rigid Generator]   Prisma, middleware,     100% deterministic
                             routes, Zod validators
   ▼
[Layer 3: Epistemic Gen.]    LLM calls, Trace,       validated at the
                             Checkpoint, Lens         boundary by Layer 2

The contract — JSON output containing a _confidence field, parseable by a Zod schema — is enforced uniformly across LLM providers. The current implementation routes to Anthropic Claude (cloud) or any OpenAI-compatible endpoint, including Ollama running local open-weight models.

Empirical evidence

Provider-agnosticism is not a claim — it is verified. The example above was transpiled and exercised end-to-end against Qwen 2.5 3B Instruct running locally via Ollama, on a personal laptop, with no cloud API and no credit card.

Input Model output Result Latency
"Contrato simples de serviço R$500/mês, 12 meses, rescisão 30 dias." {"risco":"Baixo","_confidence":0.85} Validated · returned "Baixo" ~3s
"Contrato unilateral leonino, multa 95%, sem rescisão." {"risco":"Alto","_confidence":0.9} Validated · returned "Alto" ~3s
(any input, malformed LLM JSON) {"unexpected":"object"} Zod rejected · routed to queue: "Advogados" —

The third row is the point: a small open-weight model that produced non-conforming JSON did not propagate its hallucination. The transpiler-generated validator caught the malformed output and triggered Fallback.ManualReview — a behavior the developer never wrote.

Hardware: Apple Silicon, 16 GB RAM. Model: qwen2.5:3b-instruct (Q4_K_M, ~1.9 GB). Same .epi source compiles unchanged against Anthropic Claude in cloud.

Quick start

The full setup, without cloning the repository:

# once: install Ollama and pull a small instruction-tuned model
ollama pull qwen2.5:3b-instruct
ollama serve &

# install Epi and bootstrap a project
pip install epi-lang
epi init meu-classificador
cd meu-classificador

# transpile to a runnable Next.js project
epi transpile contrato.epi --target nextjs --outdir ./app

# run it
cd app
npm install
cp .env.example .env   # pre-configured for Ollama local
npx prisma migrate dev --name init
npm run dev

To target Anthropic Claude instead, edit .env and set EPI_AI_PROVIDER=anthropic with your ANTHROPIC_API_KEY. No changes to the .epi source. No changes to the generated code.

Trace and Checkpoint

A Pulse can be decomposed into Trace steps. Each Trace can Expose intermediate reasoning fields and pause at a Checkpoint for human review before the final output is committed. 

Pulse AvaliarRespostaAluno {
    Trace InterpretarEnunciado {
        Execute: AI.reason(prompt: file("@prompts/..."))
        Expose: interpretacao, conceitos_chave, criterios_avaliacao
        Checkpoint: ReviewRequired(role: "Professor")
    }
    Trace AvaliarResposta {
        Execute: AI.classify(
            confidence_threshold: 0.85,
            on_low_confidence: Checkpoint.ReviewRequired(role: "Professor")
        )
    }
}

The transpiler emits an in-memory TraceState store, inspect / resume HTTP routes, and an audit trail of every approval or correction. Intended for high-stakes flows — pedagogical assessment, legal review, clinical triage — where reasoning must be inspected before persistence.

When to use Epi — and when not to

Use Epi when

  • Audit-by-construction is required (legal, healthcare, education, government)
  • AI-inferred values must be persisted and traceable, not just shown
  • Human-in-the-loop is structural, not exceptional
  • The domain has a meaningful prior distribution (Bayesian update genuinely helps)
  • You ship a focused product, not a general AI platform

Don't use Epi for

  • Conversational chatbots or generic assistants
  • Apps centered on complex RAG or multi-tool agents
  • Teams with a mature in-house AI platform already in place
  • Pure creative generation — confidence and checkpoint don't apply
  • Sub-100ms latency paths

The full honest list of current gaps is documented in LIMITATIONS.md.
